# 静态编译验证报告（Windows → 国产 Linux，零系统依赖）

> 结论先行：**Go 本身没有「Linux 版本限制」**。你在 Ubuntu 上编出来、到麒麟跑不起来，是因为产物被 CGO 链到了构建机的 glibc 上。关掉 CGO，Go 产出的是**完全静态 ELF**：没有动态加载器、没有 `DT_NEEDED`、没有 `GLIBC_*` 符号引用。本报告在 Windows 机器上实测了 4 种架构，全部通过。
>
> 验证环境：Windows，Go 1.27.4 windows/amd64，`CGO_ENABLED=0`，依赖仅 `github.com/xuri/excelize/v2 v2.11.1`（纯 Go）。

---

## 一、为什么「Ubuntu 编译 → 麒麟跑不起来」

典型报错：

```
./exceltool: /lib64/libc.so.6: version `GLIBC_2.34' not found
./exceltool: /lib64/libc.so.6: version `GLIBC_2.32' not found
```

原因不是 Go，而是**产物是动态链接的，并且要求的 glibc 版本高于目标机**：

| | 构建机 | 目标机 |
|---|---|---|
| 系统 | Ubuntu 22.04（常见 CI 镜像） | 银河麒麟 V10 / 统信 UOS 20 |
| glibc | 2.35 | **2.28** |
| 结果 | 二进制里写死了 `GLIBC_2.34` 等符号版本 | 找不到 → 直接拒载 |

**触发条件只有一个：`CGO_ENABLED=1`。** 一旦开启 cgo，链接的就不再是 Go，而是构建机的 libc，产物从此和构建机的 glibc 版本绑死。

### 这个仓库里是谁把 CGO 打开的

| 证据 | 位置 |
|---|---|
| `CGO_ENABLED=1` + 交叉 C 编译器 | `Makefile:24` `GOOS=linux GOARCH=arm64 CGO_ENABLED=1 CC=aarch64-linux-gnu-gcc` |
| `fyne-cross`（Fyne 官方交叉编译方案，本质是跑 Docker + 带 cgo 的镜像） | `Makefile:27-29` |
| 依赖里有 Fyne 全家桶 | `go.sum`：`fyne.io/fyne/v2 v2.4.3`、`fyne.io/systray`、`fyne-io/glfw-js`、`go-gl/gl`、`go-gl/glfw/v3.3`、`go-text/render` |
| 桌面 GUI 需要 OpenGL / X11 / 字体栈 | 同上，全部是 cgo 包 |

也就是说：**是 Fyne 干的，不是 Go 干的。** README 里已经写了「从 Fyne 迁到 Web 技术栈」，但依赖没清、Makefile 没改，所以构建仍然走 cgo 老路。

## 二、实测：Windows 上交叉编译 4 种 Linux 架构

用与目标架构完全一致的最小程序验证（`net/http` + `go:embed` + `excelize` 删除行列），
构建命令只有三个环境变量：
```powershell
$env:CGO_ENABLED = "0"
$env:GOOS  = "linux"
$env:GOARCH = "arm64"      # amd64 / arm64 / loong64 / mips64le
go build -trimpath -ldflags "-s -w" -o exceltool .
```

**不需要** WSL、Docker、zig、`aarch64-linux-gnu-gcc`、sysroot —— 一个 Go 安装包即可。

### 产物校验结果

v3.1.0 正式产物（`scripts/build.ps1` 一次构建，Windows 上完成）：

| 目标 | 用途 | 体积 | ELF 类型 | PT_INTERP | DT_NEEDED | GLIBC_* |
|---|---|---|---|---|---|---|
| `linux-amd64` | 麒麟 V10 / UOS x86_64 | 12.4 MB | `ET_EXEC` x86_64 | 无 | 无 | 无 |
| `linux-arm64` | 飞腾 / 鲲鹏 | 11.6 MB | `ET_EXEC` aarch64 | 无 | 无 | 无 |
| `linux-loong64` | 龙芯 3A5000+ | 12.4 MB | `ET_EXEC` LoongArch | 无 | 无 | 无 |
| `linux-mips64le` | 存量龙芯 3A3000/4000 | 13.6 MB | `ET_EXEC` MIPS | 无 | 无 | 无 |

四个产物**全部判定为 FULLY STATIC**：

```
file      : exceltool-linux-arm64
elf       : 64-bit aarch64 ET_EXEC
PT_INTERP : <none>            ← 没有动态加载器
PT_DYNAMIC: False             ← 根本没有 .dynamic 段
DT_NEEDED : <none>            ← 不依赖任何 .so
GLIBC_*   : <none>            ← 一个 glibc 符号都不引用
verdict   : FULLY STATIC
```

校验器：`scripts/check-elf.ps1`（直接解析 ELF 头、程序头、动态段，不依赖外部工具）。

### 对照实验：为什么不要加 `-buildmode=pie`

同样的代码加 `-buildmode=pie`：

```
elf       : 64-bit x86_64 ET_DYN
PT_INTERP : /lib64/ld-linux-x86-64.so.2   ← 又开始要求宿主机的动态加载器
DT_NEEDED : <none>
GLIBC_*   : <none>
verdict   : DYNAMIC
```

结论：**分布式交付不要用 `-buildmode=pie`**，默认的 `ET_EXEC` 才是零依赖。

### 功能验证（同一份代码在 Windows 上跑起来）

```
GET /                 → 内嵌 HTML 正常返回（go:embed，无 webview）
POST /api/process     → {"status":"ok","rows":8,"cols":4,"sheets":["Sheet1"]}
```
（对 `testdata/employee.xlsx` 删除首行首列，excelize 正常读写。）

## 三、三道闸门：保证以后不会悄悄退回动态链接

1. **构建脚本强制 `CGO_ENABLED=0`**，不依赖开发者记忆 —— 见 `scripts/build.ps1`。
2. **构建前依赖扫描**：`go list -deps -f '{{if .CgoFiles}}{{.ImportPath}}{{end}}'`
   任何带 C 代码的依赖直接让构建失败。当前应为空；一旦有人引入 Fyne / Wails / `mattn/go-sqlite3`（cgo 版）/ `os/user` 的 cgo 分支，立刻红。
3. **构建后 ELF 校验**：`scripts/check-elf.ps1`，非 `FULLY STATIC` 直接 fail，不产出"看起来能跑"的包。

推荐的完整参数：

```powershell
go build -trimpath -tags "netgo osusergo" `
  -ldflags "-s -w -extldflags '-static'" `
  -o bin/exceltool-linux-arm64 ./cmd/exceltool
```

- `-tags netgo`：强制纯 Go DNS 解析器（不碰 libc 的 `getaddrinfo`）
- `-tags osusergo`：强制纯 Go 的 `/etc/passwd` 解析（不碰 libc 的 `getpwnam`）
- `-extldflags "-static"`：即使哪天有人误开 cgo，也让外部链接强制静态
- `-trimpath`：去掉本机构建路径，产物可复现

## 四、关于 webview：本方案一个 webview 都不依赖

| 方案 | 链接期依赖 | 能不能用 |
|---|---|---|
| Fyne（现仓库遗留） | OpenGL / X11 / GLFW / 字体库，**必须 cgo** | ❌ 就是它导致 glibc 绑定 |
| Wails | WebView2（Windows）/ **WebKitGTK（Linux）** | ❌ 需要系统装 webkit2gtk-4.x |
| Electron / Tauri / CEF / QtWebEngine | 一整套 Chromium 运行时，几百 MB | ❌ |
| **本方案：`net/http` + `go:embed` + 系统浏览器** | **无**（`net/http` 是 Go 标准库，纯 Go） | ✅ |

区别在于：

- **webview 是“库”**，要链接进进程，必须随包交付或要求客户机预装（麒麟上经常没有 webkit2gtk）。
- **浏览器是“应用程序”**，程序只是 `http://127.0.0.1:端口` 交给它打开。进程本身零链接依赖，浏览器崩了也不影响后端。麒麟 V10 / UOS 20 桌面版自带 Firefox ESR（或奇安信/360），这是操作系统镜像的既有能力，不需要你交付。

如果你连“调用浏览器”也要去掉，那么 Linux 上可选项只有两个，且都有代价：

1. **纯 Go TUI**（bubbletea 等，无 cgo）：彻底零依赖，但交互从图形界面变成终端，属于功能变更。
2. **纯 Go 的 X11 客户端**（`BurntSushi/xgb` 是纯 Go，不链 X11 库）：能画窗口，但要自己实现控件、布局、中文字体渲染、输入法，等于重做一个 GUI 框架；且 Wayland 会话下不兼容。

**建议**：保持 Web UI + 系统浏览器。它已经是"不依赖任何系统/Web 库"的最优解 —— 链接期依赖为 0，运行时只借用桌面自带的浏览器。

## 五、兼容性基线（麒麟 / UOS）

| 项 | 静态 Go 产物的情况 |
|---|---|
| glibc | **完全不需要**，任意版本（2.17 / 2.28 / 2.35）都一样 |
| Linux 内核 | Go 1.27 要求 **3.2+**；麒麟 V10 = 4.19，UOS 20 = 4.19/5.10，老麒麟 V4 = 3.10，全部满足 |
| 动态加载器 `/lib64/ld-linux-*` | 不需要 |
| `/usr/share/zoneinfo`（时区库） | 最小化镜像可能没有 → 源码里加 `import _ "time/tzdata"` 内嵌时区数据 |
| CA 根证书 | 只在需要访问 HTTPS 外网时才有意义；纯本地工具无影响。若需要，用 `crypto/x509` 内嵌证书包 |
| 中文字体 | 不需要。excelize 只把字体名写成字符串，不做渲染 |
| CPU 指令集 | 默认 `GOAMD64=v1`，2003 年后的 x86_64 都能跑；不要手动调高（`v3` 会让老机器直接 SIGILL） |

## 六、复现步骤

```powershell
# 1. 装 Go（1.23+ 即可，这里用 1.27.4），加入 PATH
# 2. 仓库根目录准备模块
go mod init exceltool
go mod tidy

# 3. 一次产出全部目标（含静态性自检）
.\scripts\build.ps1 -Version 3.1.0

# 4. 单独校验某个产物
.\scripts\check-elf.ps1 -Path bin\exceltool-linux-arm64
```

到目标机后（麒麟 / UOS）：

```bash
chmod +x exceltool-linux-arm64
./exceltool-linux-arm64 --no-browser
ldd ./exceltool-linux-arm64      # 应输出：not a dynamic executable
```

**分发注意**：用 zip 传文件会丢可执行权限，到 Linux 上必须 `chmod +x`；用 `tar.gz` 打包能保留权限。
